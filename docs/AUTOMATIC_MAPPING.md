# การเปรียบเทียบอัตโนมัติ รุ่น 0.2

ระบบเสนอคู่มาตรฐาน–รายวิชาและเกณฑ์รายข้อเพื่อช่วยผู้จัดทำรวบรวมหลักฐาน ผู้เชี่ยวชาญยังเป็นผู้วินิจฉัยความสอดคล้อง การวิเคราะห์ไม่แก้ตาราง ไม่ให้สถานะรับรอง ไม่ส่งคิวผู้เชี่ยวชาญ และไม่เผยแพร่ผลเอง

## ขั้นค้นคู่มาตรฐาน

- อ่าน `standardRef` จากรายละเอียดรายวิชา เลือกข้อความอ้าง TPQI ก่อน แล้วค้นด้วยรหัสเต็ม ชื่ออาชีพในอ้างอิง และชื่อรายวิชาตามลำดับ
- ค้นสูงสุด 3 คำ คำละ 18 รายการ อ่านรายละเอียดไม่เกิน 8 มาตรฐาน โดยให้ผลจากคำค้นอ้างอิงอยู่ก่อนชื่อรายวิชา ตรวจทุกระดับในรายการที่อ่าน
- จัดลำดับด้วยรหัส UoC เต็มที่ตรง, ชื่ออาชีพที่ปรากฏในอ้างอิง, รหัสที่ยังคลุมเครือ และคำร่วม ตามลำดับ ไม่ใช้รหัสท้าย `103B` แทนรหัสเต็ม `CIP-NPEC-103B`
- ระดับที่ขัดกับเอกสารอ้างอิงเลือกไม่ได้ หากต้นทางไม่พร้อมแสดงการใช้ snapshot หรือจำนวนรายละเอียดที่อ่านไม่สำเร็จ พร้อมขอบเขตการค้นจริง
- การค้นนี้ไม่สำรวจทั้งคลัง ไม่เป็นหลักฐานว่าไม่มีคู่ที่เหมาะสม และไม่สร้างงานเทียบแทนผู้จัดทำ

## ขั้นวิเคราะห์รายข้อ

วิธี `document-first-lexical/1.0.0` ทำงานบนข้อมูลที่ตรึงในฉบับงาน แยกคำภาษาไทยด้วย `Intl.Segmenter` ตัดคำทั่วไปและตัวเลขล้วน จัดอันดับคำร่วมของข้อกำหนดกับเกณฑ์ PC ด้วย cosine ของน้ำหนักคำตามความถี่ในระดับมาตรฐานที่เลือก

อ้างอิง UoC เต็มอยู่ก่อนคะแนนข้อความเสมอ สำหรับคู่ที่ไม่มีรหัสตรง ต้องมีคำเฉพาะร่วมอย่างน้อย 2 คำ และค่า cosine ตั้งแต่ 0.12 จึงนำเข้ารายการเสนอ เก็บไม่เกิน 3 คู่ต่อข้อกำหนด เกณฑ์ 0.12 เป็นเกณฑ์คัดค้นเชิงเทคนิคที่ยังไม่ได้สอบเทียบกับผลผู้เชี่ยวชาญ ไม่ใช่เกณฑ์ผ่าน ไม่ใช่ confidence และไม่แสดงเป็นร้อยละสมรรถนะ

ตรวจคำร่วมในผลลัพธ์ สมรรถนะ จุดประสงค์ และคำอธิบายรายวิชาเป็นหลักฐานสนับสนุน พร้อมเก็บข้อความตรงตามต้นฉบับ การมีข้อความสนับสนุนเพียงอย่างเดียวไม่ทำให้ข้อกำหนดที่ไม่มีคู่ถูกนับว่าครบ ไม่เพิ่มตัวหารจากข้อความซ้ำ

ผลแสดงทั้งข้อกำหนดรายวิชาที่ยังไม่มีคู่ และเกณฑ์ TPQI ที่ยังไม่ได้รับการเสนอคู่ ตัวเลขเป็นจำนวนที่ค้นพบเท่านั้น ไม่ได้หมายถึงความครอบคลุมที่รับรองแล้ว ตรวจอ้างอิงต่างระดับ คำปฏิเสธ หลักฐานเชิงทฤษฎีเทียบกับงานปฏิบัติ และความปลอดภัยเป็นจุดที่ต้องให้คนตรวจ ไม่ถือว่ากฎคำสำคัญนี้พบช่องว่างเชิงวิชาการได้ครบ

รุ่นนี้วิเคราะห์เฉพาะข้อกำหนดที่มีในตารางและหนึ่งระดับที่เลือก รองรับเกณฑ์ PC ไม่เกิน 3,000 ข้อต่อการวิเคราะห์ ผลวิเคราะห์ที่เก็บได้สูงสุด 1 MB เมื่อเกินขอบเขตตอบข้อผิดพลาดที่ระบุสาเหตุ ไม่ตัดรายการทิ้งเงียบ ๆ

## ใช้ข้อเสนอและตรวจสอบย้อนหลัง

- `mapping_analyses` เก็บผลแยกจาก `mappings` พร้อม mapping ID, revision, input hash, ผู้สั่งวิเคราะห์, วันเวลา และรุ่นวิธีวิเคราะห์
- การสั่งวิเคราะห์ไม่แก้ hash หรือสถานะงาน การเลือกใช้ข้อเสนอผ่านคำสั่งแยกและสร้างฉบับร่างใหม่ ตรวจ revision/hash ซ้ำภายในธุรกรรม
- ตรวจ candidate ID จากผลที่บันทึกฝั่งเซิร์ฟเวอร์ ไม่รับข้อความหลักฐานจาก client เป็นผลอัตโนมัติ ห้ามข้ามงาน ใช้ผลเก่า หรือใช้ข้อเสนอที่ขัดระดับ
- ไม่เขียนทับแถวที่มีเกณฑ์หรือมีผลวินิจฉัยอยู่แล้ว เลือกได้หนึ่งข้อเสนอต่อแถวต่อครั้ง การเชื่อมเกณฑ์เพิ่มยังทำผ่านตารางแบบ many-to-many ได้
- การใช้ข้อเสนอคงสถานะ `INSUFFICIENT_EVIDENCE` ทุกข้อ ไม่เปลี่ยน `referenceStatus` เป็น VERIFIED และล้างเครื่องหมายยืนยันขอบเขต/เอกสาร เพื่อให้คนตรวจฉบับใหม่ก่อนส่งผู้เชี่ยวชาญ
- audit ของฉบับใหม่ระบุ analysis ID และรายการที่เลือก พิมพ์ผลวิเคราะห์พร้อมสถานะไม่รับรอง รุ่นวิธีและ hash ได้

API: `POST /api/recommendations`, `GET /api/mappings/:id/analyses`, `POST /api/mappings/:id/analyze`, `POST /api/mappings/:id/apply-analysis` สิทธิ์สั่งวิเคราะห์/ใช้ผลเป็นผู้จัดทำที่ยังมีบทบาท editor หรือ admin ในฉบับร่างเท่านั้น

## การตรวจรับและข้อจำกัด

Unit tests เพิ่ม 15 กรณี และ HTTP checks เพิ่ม 20 จุดกับ Cloudflare worker จริงในเครื่อง ครอบคลุมลำดับอ้างอิงเต็ม/ส่วนท้าย ระดับผิด ความไม่เปลี่ยนแปลงของฉบับเดิม การรักษาหลักฐาน ข้อที่ไม่มีคู่ งานเดิม การใช้ผลเก่า และสิทธิ์ ในการค้นรายวิชา `20100-1001` จากต้นทางวันที่ 11 กันยายน 2569 ได้คำแนะนำ 5 รายการจากรายละเอียดที่อ่าน 6 รายการ นี่เป็นตัวอย่างการเชื่อม API ไม่ใช่การประเมินความถูกต้องของคู่เทียบโดยผู้เชี่ยวชาญ

ยังไม่มี LLM/embeddings, OCR อัตโนมัติ, การเทียบทั้งคลังตามกำหนดเวลา หรือการวัด precision/recall กับชุดเฉลยที่ผู้เชี่ยวชาญรับรอง ก่อนพิจารณาใช้ผลเป็นข้อวินิจฉัยต้องสอบเทียบกับชุดอ้างอิงจริงและเพิ่มกฎ/หลักฐานด้านบริบท ระดับคุณภาพ และวิธีประเมินตามนโยบายสถานศึกษา
