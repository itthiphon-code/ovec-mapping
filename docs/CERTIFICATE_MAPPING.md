# ใบรับรองที่สอบผ่าน → รายวิชาที่เสนอให้พิจารณาเทียบโอน

รุ่น 0.5 · 11 กันยายน 2569

หน้าหลักเริ่มจากค้นมาตรฐานในใบรับรอง เลือกระดับและ UoC ที่สอบผ่านจริง โดยไม่เลือกแทนผู้เรียนล่วงหน้า ระบบแสดงรายวิชาพร้อมเปอร์เซ็นต์ความคล้าย หลักฐาน UoC/EoC/PC และหน่วยอ้างอิงที่ไม่ได้เลือก กดเตรียมคำร้องแล้วรหัสวิชา สาขา ระดับและขอบเขตใบรับรองจะอยู่ในแบบคำร้องให้ตรวจแก้ ก่อนแนบเอกสารคุณวุฒิที่เจ้าของอัปโหลดไว้ตามขั้นตอนเดิม

การเลือกขอบเขตเป็นข้อมูลจากผู้ใช้ ไม่ใช่การยืนยันความแท้ อายุ หรือสิทธิ์ของใบรับรอง ระบบไม่ได้อ่านใบรับรองด้วย OCR และไม่มีการตรวจเลขใบรับรองกับ TPQI อัตโนมัติ การรับรองและตัดสินหน่วยกิตยังผ่านผู้เชี่ยวชาญ ผู้มีอำนาจ และนโยบายสถานศึกษาตามระบบเดิม ไม่มีการอนุมัติจากคะแนนหรือสร้างคำร้องเองเมื่อกดดูผล

## ชุดคำนวณ

- `certificate-20260911-e5-01` อ้างอิง immutable snapshot `bulk-20260911-e5-01` (9–11 กันยายน 2569)
- 1,022 มาตรฐาน; 2,098 ระดับที่มี PC; คัดกรองทุกระดับกับ 6,277 วิชาที่มีรายละเอียด ปวช./ปวส.
- เก็บ 20 วิชาแรกต่อระดับตามรหัสอ้างอิงเต็ม ชื่ออ้างอิง ระดับ และ cosine พร้อมทุกวิชาที่มีรหัสหรือชื่ออ้างอิงตรง รวม 42,417 คู่ระดับ–รายวิชา (4,070 รายวิชาไม่ซ้ำในชุดผลละเอียด)
- อีก 11 วิชามีข้อมูลไม่พอ; 612 รายการระดับอื่นอยู่นอกขอบเขต
- ใช้เวกเตอร์ E5 จริงจากโมเดล `Xenova/multilingual-e5-small`, revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`, q8, 384 มิติ ที่คำนวณและบันทึกในรอบก่อน ไม่มีคะแนนจำลอง
- Query prefix ทั้งสองฝั่ง, ข้อความเต็มแบ่งทุก 320 Unicode codepoints, weighted normalized mean ตามจำนวนอักขระ เหมือนรอบต้นทาง
- คัดกรองด้วย centroid ของ PC ทั้งระดับ ต่อจากนั้นเทียบทุก target กับทุก PC ในระดับ เก็บ PC ที่ cosine สูงสุดแยกแต่ละ UoC เพื่อให้เลือกบางหน่วยแล้วเปลี่ยนผลได้ทันที
- เมื่อเลือก UoC ใช้เฉพาะ PC ในหน่วยที่เลือก ให้รหัสเอกสารตรงมาก่อน cosine แล้วเฉลี่ย max(0, cosine) ทุก target × 100 ปัดหนึ่งตำแหน่ง ไม่มีหน่วยหรือไม่มี PC ให้แสดงว่าง ไม่แสดง 0% แทนหลักฐานที่ขาด

การเปลี่ยน UoC จัดอันดับใหม่ภายในชุดคัดไว้ของระดับ ไม่ใช่การคำนวณละเอียดทุกคู่ทั้งคลังหรือการคัดกรองทุกวิชาใหม่จากแต่ละ subset อาจมีวิชาอื่นนอกผล หน้าเว็บและรายงานระบุข้อจำกัดนี้ คะแนนไม่ใช่ความครอบคลุมหลักสูตร หน่วยกิต หรือความน่าจะเป็น และยังไม่ได้สอบเทียบกับผลผู้เชี่ยวชาญ

## หลักฐานและการจัดเก็บ

ไฟล์ใหม่อยู่ `public/certificates/certificate-20260911-e5-01/` พร้อมดัชนี hash ที่ผูกกับ `lib/certificate-registry.json` ไฟล์จัดเก็บเป็น JSON gzip แบบ lossless เพื่อลดขนาดจาก 236 MB เหลือ 34 MB และตรวจ SHA-256 ของเนื้อหาหลังคลายข้อมูล (เนื้อหาหลักฐานและคะแนนเดิมทุก byte) API `/api/certificates` และ `/api/certificates/:id` อ่านและตรวจ SHA-256 ผ่าน ASSETS เอกสารรายวิชาอ่านจากผลต้นทางและตรวจ hash ก่อนแสดงรายละเอียด ไม่มี schema migration หรือการเปลี่ยนผลรับรองเดิม

ไฟล์ต่อมาตรฐานเก็บสำเนามาตรฐานเดิมพร้อม provenance, รหัสระดับ, PC, target เดิม และคู่ index–cosine แยก UoC ทุก target สามารถตามกลับเอกสารต้นฉบับและผลรอบเดิมได้ คำร้องเก็บข้อมูลขอบเขตจากผู้ใช้ใน note เป็นข้อมูลรอตรวจ ไม่ถือเป็นหลักฐานที่ยืนยันแล้ว

## ตรวจสอบและสร้างซ้ำ

`npx tsx scripts/compute-certificate-mapping.ts` ใช้ public artifacts รอบเดิมและ `tmp/bulk-cache/vectors-<revision>.jsonl` ที่คำนวณจากโมเดลจริงเท่านั้น ถ้าเวกเตอร์ขาดจะหยุด หากดัชนีรอบเสร็จแล้วจะปฏิเสธเขียนทับ การสร้างรอบใหม่ต้องเปลี่ยน RUN/SOURCE เป็นรอบใหม่ที่ตรวจต้นทางแล้วและอัปเดต registry ผ่านสคริปต์

`npx tsx scripts/verify-certificate-artifacts.ts` ผ่านทุก 1,022 มาตรฐาน / 42,417 คู่ / 1,198,191 PC–cosine tuples ตรวจ hash ทั้งมาตรฐานและรายวิชา, target ตรงต้นฉบับ, PC อยู่ใน UoC/ระดับจริง, selected subset ไม่ใช้หน่วยอื่น และสูตรคะแนนทุกหน่วย ไฟล์ใหญ่สุด 2,378,486 bytes
