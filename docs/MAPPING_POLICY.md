# หลักเกณฑ์ mapping ที่อิงหลักฐานและตรวจสอบย้อนกลับ

ฉบับข้อเสนอ 1.0 · เกณฑ์ภายในสำหรับคณะผู้เชี่ยวชาญตรวจทานก่อนประกาศใช้

## 1. หลักวิชาการ

เลือกใช้ **การเทียบข้อกำหนดสมรรถนะที่อิงเอกสารต้นฉบับและการตรวจของผู้เชี่ยวชาญ** (document-first, criterion-referenced competency mapping) ไม่มีหลักฐานว่าตัวเลขจากโมเดลหรือวิธีเดียวให้ผล “น่าเชื่อถือที่สุด” ในทุกสาขา ความน่าเชื่อถือจึงต้องมาจากหลักฐาน ความครบถ้วน ความทำซ้ำได้ และผลทดสอบกับผู้เชี่ยวชาญ

โครงสร้างต้องลงถึง EoC และ PC พร้อมเงื่อนไขประเมิน ตัวอย่างเอกสารหน่วยสมรรถนะของ [TPQI](https://tpqinet-api.tpqi.go.th/qualifications/unitinfo/14828) แสดงเกณฑ์การปฏิบัติงาน ทักษะ/ความรู้ หลักฐาน และขอบเขตควบคู่กัน จึงไม่พอที่จะจับคู่เพียงชื่อ UoC กับชื่อรายวิชา

## 2. ลำดับหลักฐาน: แยกความน่าเชื่อถือของแหล่งกับความละเอียดของข้อกำหนด

| ลำดับ | แหล่งหลักฐาน | ใช้ทำอะไร |
|---|---|---|
| 1 | เอกสารมาตรฐานของ TPQI และหลักสูตรที่เจ้าของหลักสูตรประกาศ พร้อมฉบับ/วันมีผล | ยืนยันตัวมาตรฐาน เนื้อหาข้อกำหนด และอ้างอิงโดยตรง |
| 2 | ประกาศแก้ไข ตารางเทียบฉบับ คำชี้แจงที่ออกโดยเจ้าของมาตรฐาน/หลักสูตร | พิจารณาการเปลี่ยนรหัส ชื่อ ขอบเขต และการใช้แทนฉบับเดิม |
| 3 | ฐานข้อมูลทางการ/API ที่ตามกลับเอกสารได้ | นำเข้า ค้น และสร้างร่าง; ต้องตรวจหัวข้อสำคัญกับฉบับต้นฉบับ |
| 4 | แผนการจัดการเรียนรู้ ใบงาน rubric และแผนประเมินที่สถานศึกษารับรอง | เพิ่มหลักฐานความครอบคลุมและการประเมิน แต่ไม่เปลี่ยนข้อความหลักสูตร |
| 5 | ผลจับคู่เดิม คำค้น embeddings และข้อเสนอ AI | เสนอผู้สมัครและอธิบายร่าง; ไม่เป็นหลักฐานแทนข้อกำหนด |

กรณี API กับ PDF ขัดกัน เปิด `SOURCE_CONFLICT` ให้ผู้ดูแลข้อมูลตรวจว่าเป็นคนละฉบับหรือดึงผิด ไม่เลือก PDF ใดเพียงเพราะเป็นไฟล์ PDF ต้องยืนยันเจ้าของ ฉบับที่ใช้บังคับ และวันที่อ้างอิงด้วย

ข้อมูลใน “อ้างอิงมาตรฐาน” มีน้ำหนักสูงสำหรับระบุว่าจะไปตรวจมาตรฐานใด แต่การอ้างถึงทั้งอาชีพไม่ได้แปลว่ารายวิชาครอบคลุมทุก UoC ของอาชีพนั้น

## 3. การระบุตัวตนก่อนเทียบ

เก็บรหัสเต็มและข้อความดิบ ไม่ตัด prefix/suffix ของรหัสเพื่อถือว่าตรงกัน และไม่ใช้ความคล้ายชื่อเพื่อยืนยันรหัส หลักฐานระบุตัวตนต้องพิจารณาเจ้าของมาตรฐาน สาขา อาชีพ รหัส ระดับ ฉบับ และวันมีผลร่วมกัน

กำหนดสถานะอ้างอิง `EXACT_REFERENCE`, `AMBIGUOUS_REFERENCE`, `LEVEL_MISMATCH`, `VERSION_UNRESOLVED`, `SOURCE_CONFLICT`, `NO_REFERENCE` ถ้าคนละระดับ/ฉบับ ต้องใช้ตารางเปลี่ยนฉบับหรือคำวินิจฉัยที่มีอำนาจรองรับ ไม่เปลี่ยนไปใช้ระดับที่ใกล้ที่สุดอัตโนมัติ ระดับสูงกว่าไม่หมายความว่าครอบคลุมข้อกำหนดระดับต่ำกว่าทุกข้อ

สถานะ `EXACT_REFERENCE` ยืนยันว่าหาตัวมาตรฐานถูกเท่านั้น ผลรายข้อยังอาจเป็นบางส่วนหรือไม่ครอบคลุมได้

## 4. การแตกข้อความเป็นข้อกำหนด

ฝั่ง TPQI: `มาตรฐาน/ฉบับ → อาชีพและระดับ → UoC → EoC → PC` เก็บ required knowledge, required skills, range, prerequisites, evidence guide และ assessment conditions เมื่อเอกสารมี

ฝั่งรายวิชา: `หลักสูตร/ปี/ระดับ/สาขา → รายวิชา/ฉบับ → ผลลัพธ์ → สมรรถนะ → จุดประสงค์ → ข้อความคำอธิบาย → เกณฑ์ประเมิน` แต่ละหน่วยข้อความมีชนิดและตำแหน่งเดิม ห้ามนำการกล่าวถึงหัวข้อในคำอธิบายไปยืนยันว่าผู้เรียนทำได้ตามเกณฑ์ปฏิบัติ

ถ้าผลลัพธ์หนึ่งมีหลายการกระทำ แยกเป็นข้อย่อยพร้อม parent และ original span โดยผู้ตรวจยืนยันการแตกข้อความ ข้อความดิบอยู่ครบเสมอ ใช้คำกริยา งาน/วัตถุ บริบท เครื่องมือ ระดับความรับผิดชอบ คุณภาพ และวิธีประเมินเป็นมิติพิจารณา ไม่ตัดสินจากลำดับคำกริยาเพียงอย่างเดียว

## 5. กระบวนการสร้างตาราง

1. ล็อกขอบเขตรายวิชา/มาตรฐาน/ฉบับ และทิศทางการใช้งาน
2. ตรวจการอ้างอิงในเอกสารก่อน สร้าง candidate ที่แสดงหลักฐานว่าเลือกมาตรฐานนี้เพราะอะไร
3. กรณีไม่ระบุอ้างอิงหรือยังคลุมเครือ ค้นคำศัพท์เฉพาะ รหัสเต็ม ชื่ออาชีพ สาขา และความหมาย เพื่อให้ผู้เชี่ยวชาญเลือก ห้ามซ่อนความคลุมเครือด้วยคะแนนสูง
4. แตกข้อกำหนดทั้งสองฝั่ง ตรวจตารางและ OCR โดยเฉพาะรหัส ตัวเลข หน่วยวัด คำปฏิเสธ และข้อความต่อหน้ากระดาษ
5. สร้างรายการเทียบแบบ many-to-many พร้อมหลักฐานทั้งสองฝั่ง เหตุผล มิติที่ตรง และช่องว่าง
6. ตรวจข้อบังคับระดับ/บริบท/ความปลอดภัย/การประเมิน และข้อกำหนดทั้งหมดที่ยังไม่มีคู่
7. ผู้เชี่ยวชาญตรวจรายข้อ บันทึกความเห็นอิสระและวินิจฉัยความเห็นต่าง
8. อนุมัติ revision ที่คงที่ บันทึกผู้ลงนามและ manifest แล้วจึงเผยแพร่

การใช้ AI เป็นตัวเลือก ระบบต้องสร้างและรับรอง mapping ด้วยมือได้ครบแม้ AI ใช้งานไม่ได้ โมเดลได้รับเฉพาะข้อความและรายการ evidence ID ที่มีอยู่ ส่งผลตาม schema ที่ validate ได้ และไม่มีเครื่องมืออนุมัติ/เผยแพร่ ข้อความในเอกสารถือเป็นข้อมูล ไม่ใช่คำสั่งให้เปลี่ยน workflow

## 6. ผลรายข้อที่ใช้

| สถานะ | ความหมายและหลักฐานขั้นต่ำ |
|---|---|
| `FULL` | ข้อกำหนด งาน บริบท และระดับสอดคล้องครบตามขอบเขตที่เทียบ มีหลักฐานตรงและผู้ตรวจยืนยัน |
| `PARTIAL` | มีส่วนที่ตรง แต่ยังขาดงาน บริบท ระดับคุณภาพ หรือการประเมิน ต้องระบุสิ่งที่ขาดอย่างเจาะจง |
| `NONE` | มีข้อมูลพอและตรวจแล้วว่าไม่ครอบคลุม พร้อมเหตุผล |
| `INSUFFICIENT_EVIDENCE` | ขาดเอกสาร/หน้า/รายละเอียด จึงยังตัดสินไม่ได้ |
| `CONFLICT` | ข้อกำหนดหรือแหล่งข้อมูลขัดกัน ต้องแก้ก่อนยืนยัน |
| `NOT_APPLICABLE` | ยกเว้นได้ตามขอบเขต/เกณฑ์ที่มีเอกสารและผู้มีอำนาจอนุมัติเท่านั้น |

เก็บ `relation_status` แยกจาก `assessment_status = VERIFIED / MISSING / INCOMPATIBLE / NOT_REQUIRED_BY_POLICY` เพื่อไม่ทำให้ “หลักสูตรครอบคลุม” กลายเป็น “ผู้เรียนมีสมรรถนะแล้ว” และแยก `reference_status`, `source_verification_status`, `review_status` ออกจากกัน

## 7. การรายงานความครอบคลุม

ไม่ใช้ค่า cosine similarity หรือความมั่นใจของโมเดลเป็นร้อยละสมรรถนะ ไม่ใช้ 60/80 เปอร์เซ็นต์ตัดสินเทียบโอนจนกว่าองค์กรจะกำหนดเกณฑ์ที่มีฐานอำนาจและตรวจสอบความเหมาะสม

กำหนดชุดข้อกำหนดเป้าหมาย `T` ที่ตกลงก่อนเริ่ม mapping และผ่านการตรวจความครบถ้วน:

```text
verified_coverage = 100 × จำนวน target ที่ FULL และผ่าน review / จำนวน target ที่ต้องประเมิน
review_completeness = 100 × จำนวน target ที่ผู้ตรวจลงความเห็นแล้ว / จำนวน target ที่ต้องประเมิน
```

คำนวณจาก target ไม่ซ้ำ ค่า `PARTIAL`, `NONE`, `INSUFFICIENT_EVIDENCE`, `CONFLICT` ยังอยู่ในตัวหารและไม่เพิ่มตัวเศษ `NOT_APPLICABLE` ออกจากตัวหารได้ต่อเมื่อมีข้อยกเว้นที่อนุมัติ พร้อมแสดงจำนวนที่ถูกยกเว้น ถ้าตัวหารเป็นศูนย์แสดง “ยังไม่มีฐานคำนวณ” หากแหล่งข้อมูลยังไม่ครบแสดง “คำนวณจากขอบเขตที่ตรวจพบเท่านั้น” และไม่รับรองว่าเป็นทั้งรายวิชา/มาตรฐาน

ต้องแสดงสองมุมแยกกัน: (ก) ข้อกำหนดรายวิชาเป้าหมายที่ชุด TPQI รองรับ และ (ข) ข้อกำหนด TPQI ที่รายวิชารองรับ ทั้งสองมีตัวหารต่างกันและไม่ใช่ค่าผกผัน ถ้าต้องให้น้ำหนัก ให้คณะผู้เชี่ยวชาญกำหนดรายข้อก่อนวิเคราะห์ เก็บเวอร์ชัน และแสดงผลแบบไม่ถ่วงน้ำหนักควบคู่เพื่อให้ตรวจสอบได้

ผลลัพธ์/สมรรถนะ/คำอธิบายที่พูดถึงงานเดียวกันเชื่อมเป็นหลักฐานสนับสนุน ไม่เพิ่มตัวหารสามครั้ง การรวมหลาย UoC หรือหลายรายวิชาใช้ union ของข้อกำหนดที่ผ่านการตรวจ ไม่บวกเปอร์เซ็นต์ การรวมหลายรายการที่เป็น `PARTIAL` ให้เป็น `FULL` ต้องให้ผู้ตรวจพิจารณาความครบถ้วนร่วมกันก่อน

## 8. เงื่อนไขห้ามรับรองความเทียบเท่าครบ

- ตัวมาตรฐาน รหัส ระดับ หรือฉบับยังไม่ยืนยัน
- ข้อกำหนดสำคัญที่คณะผู้เชี่ยวชาญระบุพร้อมเหตุผลยังเป็น partial/none/unknown/conflict
- มีเพียงความรู้เชิงทฤษฎีสำหรับข้อที่ต้องแสดงการปฏิบัติ หรือใช้หลักฐานการประเมินผิดวิธี/บริบทตามเอกสารที่ใช้บังคับ
- ข้อกำหนดเรื่องความปลอดภัย ใบอนุญาต เครื่องมือ สภาพแวดล้อม หรือความรับผิดชอบที่จำเป็นยังไม่ครบ
- ขาดหลักฐานสองฝั่ง หรือ OCR ของรหัส/ข้อกำหนดสำคัญยังไม่ตรวจต้นฉบับ
- ผู้จัดทำเป็นผู้ยืนยันงานของตนเอง องค์ประชุมไม่ครบ หรือผู้ตรวจไม่มีขอบเขตความเชี่ยวชาญที่กำหนด

อนุญาตให้รับรองตารางที่สรุปว่า “ครอบคลุมบางส่วน” เพื่อใช้ออกแบบการเรียน/ประเมินเพิ่มเติม แต่ต้องระบุว่าผลนี้ไม่รับรองความเทียบเท่าครบทุกข้อ การบังคับให้ปฏิบัติจริงต้องอิงข้อกำหนดที่เกี่ยวข้อง ไม่ตั้งว่า TPQI ทุกหน่วยต้องใช้วิธีเดียวกัน

## 9. การตัดสินเทียบโอนรายบุคคล

ตรวจตัวบุคคล เลขคุณวุฒิ ผู้ให้การรับรอง ชุด UoC ระดับ ฉบับ วันที่ สถานะการรับรอง และความตรงกันของชื่อ โดยเชื่อมบริการตรวจคุณวุฒิเมื่อมีช่องทางที่ได้รับอนุญาต มิฉะนั้นเก็บหลักฐานตรวจโดยเจ้าหน้าที่และผู้ตรวจ ห้ามถือไฟล์อัปโหลดว่าเป็นคุณวุฒิที่ยืนยันแล้ว

จากนั้นตรวจข้อกำหนดรายวิชาที่ mapping ยังขาด และจัดสัมภาษณ์ ชิ้นงาน ทดสอบ หรือสาธิตตามแผนประเมินที่รับรอง ผลการประเมินและเครื่องมือที่ใช้ต้องตรวจสอบย้อนกลับได้

สูตรตัดสินเชิงตรรกะที่เสนอ:

```text
eligible_for_decision =
  credential_verified
  AND mapping_revision_usable
  AND all_required_target_requirements_satisfied
  AND critical_gaps_closed
  AND institution_policy_satisfied
  AND expert_review_complete
```

ค่า `true` เปิดให้ผู้มีอำนาจพิจารณา ไม่อนุมัติเอง จำนวนหน่วยกิตมาจากรายวิชาและนโยบายที่ใช้จริง ไม่แปลง UoC เป็นหน่วยกิตด้วยอัตราส่วนคงที่ และไม่คำนวณเปอร์เซ็นต์ความครอบคลุมคูณหน่วยกิต ตรวจรายวิชาที่เคยได้รับหน่วยกิตแล้วเพื่อป้องกันบันทึกซ้ำ

## 10. การตรวจคุณภาพก่อนใช้งาน

จัดชุดอ้างอิงที่ผู้เชี่ยวชาญตรวจสองคนและชี้ขาดแล้ว แบ่งตามสาขา ระดับ อ้างอิงตรง/ไม่มีอ้างอิง ฉบับเปลี่ยน และกรณีชื่อคล้ายแต่คนละบริบท แยกชุดพัฒนาและชุดทดสอบตามตระกูลมาตรฐานเพื่อป้องกันข้อมูลซ้ำรั่วไปชุดทดสอบ

วัด candidate recall@k, precision รายสถานะ, ความถูกต้องของ citation, อัตราข้อสำคัญที่ระบบพลาด และความสอดคล้องระหว่างผู้ตรวจ เช่น Cohen's kappa เมื่อผู้ตรวจสองคนและเงื่อนไขเหมาะสม แสดง confusion matrix และขนาดตัวอย่าง ไม่อ้างค่าความแม่นยำก่อนมีผลทดสอบ

ข้อเสนอเกณฑ์ปล่อยรุ่น: ไม่มีกรณีปล่อยผ่าน critical gap ในชุด acceptance, citation ที่อนุมัติเปิดได้ถูกหลักฐานทุกแถว, ผู้เชี่ยวชาญรับรอง rubric และค่าเป้าหมายตามสาขา ทั้งนี้ “ไม่พบในชุดทดสอบ” ไม่ได้พิสูจน์ว่าอัตราผิดพลาดจริงเป็นศูนย์
