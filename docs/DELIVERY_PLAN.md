# แผนพัฒนาและเกณฑ์ตรวจรับ

แผนนี้ใช้เป็น backlog และเกณฑ์ตรวจงาน เริ่มจากเอกสาร/ข้อมูลและงานผู้เชี่ยวชาญ แล้วเพิ่มระบบช่วยค้น หลังจากมี baseline ที่เชื่อถือได้

## 1. ลำดับส่งมอบ

| ระยะ | งาน | เงื่อนไขจบ |
|---|---|---|
| 0. นโยบายและข้อมูลอ้างอิง | ตรวจระเบียบจริง คำสั่งผู้มีอำนาจ เลือกสาขานำร่อง กำหนด rubric ยืนยัน API/สิทธิ์ใช้ข้อมูล | มี policy draft, ชุดเอกสารต้นฉบับ, source contract และ rubric ที่ผู้เชี่ยวชาญตรวจ |
| 1. ฐานระบบ | บัญชี สิทธิ์องค์กร คลังเอกสาร snapshot sync catalogue/รายละเอียด ค้นมาตรฐาน/รายวิชา | นำเข้าซ้ำไม่ซ้ำข้อมูล เปิดหลักฐานได้ และสิทธิ์ข้ามองค์กรถูกปฏิเสธ |
| 2. Mapping ด้วยมือ | แตกข้อกำหนด ตรวจ OCR อ้างอิงตรง ตาราง many-to-many gap revision และ review | ผู้เชี่ยวชาญทำงานครบตั้งแต่ร่างถึงรับรองโดยไม่พึ่ง AI |
| 3. รายงานและเผยแพร่ | R01–R04 PDF/ตารางส่งออก หน้าบ้านเฉพาะฉบับรับรอง QR/version/withdrawal | พิมพ์ไทยถูก แถวครบ และตรวจที่มาทุกแถวได้ |
| 4. คำร้องเทียบโอน | ผู้เรียน คุณวุฒิ การตรวจหลักฐาน ประเมินเพิ่ม คำตัดสิน R05–R06 และทะเบียน | เดินงานรายบุคคลครบตาม policy ที่อนุมัติ ป้องกันหน่วยกิตซ้ำและรองรับอุทธรณ์ |
| 5. ระบบช่วยค้น/AI | candidate retrieval จากอ้างอิงตรงและความหมาย ข้อเสนอมีหลักฐาน evaluation | มีผลเทียบ baseline และข้อจำกัดเป็นรายสาขา เครื่องไม่สามารถอนุมัติได้ |
| 6. Pilot และ production | usability, accessibility, load, backup/restore, security, คู่มือและฝึกอบรม | เจ้าของระบบตรวจรับ workflow จริงและทีมปฏิบัติการซ้อมเหตุขัดข้องแล้ว |

ไม่ประมาณระยะเวลา/งบแน่นอนก่อนทราบทีม ปริมาณเอกสาร คุณภาพ OCR จำนวนสถานศึกษา และระบบทะเบียนปลายทาง การเพิ่ม AI ไม่ใช่เงื่อนไขที่จะทำให้ manual workflow ใช้งานไม่ได้

## 2. ชุดนำร่องที่เสนอ

เลือก 2–3 สาขาต่างลักษณะ รวมรายวิชาประมาณ 20–30 วิชาเพื่อทดสอบ workflow ไม่ใช้ขนาดนี้อ้างความแม่นยำทั้งประเทศ ต้องมีอ้างอิงตรง อ้างอิงหลายหน่วยงาน ชื่อคล้ายระดับต่างกัน หลักสูตรเก่า/ใหม่ ไม่มีอ้างอิง และ PDF สแกน/ตารางข้ามหน้า

ให้ผู้เชี่ยวชาญสองคนตรวจอิสระ เก็บข้อเห็นต่างและเหตุผลชี้ขาด ใช้กรณี `20100-1001` ที่ระดับรายการแนะนำไม่ตรงอ้างอิงเป็น regression case การจะปิด case ต้องตามมาตรฐานระดับ/ฉบับที่ถูกต้อง ไม่สร้างคู่เทียบให้ครบเพื่อผ่าน demo

|---|---|---|
| SRC-01 | catalogue คืนหน้าเดิมซ้ำแม้เพิ่ม page | หยุดพร้อม error ไม่วนจนโหลดไม่สิ้นสุดและไม่รายงาน complete |
| SRC-02 | API ล่มหรือ schema เปลี่ยน | คง snapshot ใช้งานล่าสุด แสดงเวลาข้อมูล เปิด incident และกักข้อมูลใหม่ |
| SRC-03 | รหัสวิชาเดียวอยู่สองสาขา | เก็บ identity แยก ไม่มีทับกันเพราะ code เดียว |
| SRC-04 | API/PDF ระบุอ้างอิงต่างกัน | ขึ้น SOURCE_CONFLICT และห้ามรับรองอ้างอิงจนแก้ |
| REF-01 | หลักสูตรระดับ 3 แต่ fuzzy candidate ระดับ 4 | ขึ้น LEVEL_MISMATCH ห้ามถือเป็น exact หรือเลือกแทนอัตโนมัติ |
| REF-02 | รหัสเต็มมี prefix แต่ผล parser เหลือท้ายรหัส | เก็บ raw เต็ม ไม่ใช้ท้ายรหัสเป็น exact match |

| MAP-07 | โมเดลอ้าง evidence ID/quote ที่ไม่มีจริง | schema/evidence validation ปฏิเสธผล ห้ามเข้า review เป็นหลักฐานที่ถูกต้อง |
| MAP-08 | รวมหลาย PARTIAL | ยังไม่ FULL จนผู้เชี่ยวชาญตรวจความครบถ้วนร่วมกัน |

## 4. เป้าหมายการปฏิบัติการที่เสนอ

ทดสอบเริ่มต้นที่ผู้ใช้พร้อมกัน 100 คนและปริมาณข้อมูล catalogue จริง กำหนดเป้าหมายค้น p95 ไม่เกิน 2 วินาที เปิดหน้าข้อมูลที่มี cache ไม่เกิน 3 วินาที ไม่รวมเวลาระบบภายนอก; งาน OCR/AI/PDF ทำผ่านคิวพร้อมสถานะและ retry เกณฑ์ตัวเลขนี้เป็นเป้าหมายรอตกลง ไม่ใช่ผลทดสอบที่ทำแล้ว

วัด latency, error rate, job age, queue failures, schema drift, source lag, document review backlog และ report failures แจ้งทีมปฏิบัติการตามช่องทางที่องค์กรตั้งค่า ไม่ส่งข้อมูลส่วนบุคคลลง log

## 5. สิ่งที่ต้องมีเมื่อส่งมอบ production

Source code และ migration, OpenAPI, data dictionary, ชุดนโยบาย/แม่แบบที่อนุมัติ, ชุดตรวจ mapping, รายงานผลทดสอบ, คู่มือครู/ผู้เชี่ยวชาญ/ผู้เรียน/ผู้ดูแล, ขั้นตอน backup/restore, rollback, incident, เปลี่ยนรหัสลับ และจัดการฉบับมาตรฐานที่ถอน

เกณฑ์ปิดงานคือผู้ใช้เดินงานจริงครบตั้งแต่เอกสาร → mapping → review → คำร้อง → ผลอนุมัติ → รายงาน/ทะเบียน ภายใต้สิทธิ์ที่ถูกต้อง ไม่ใช่แค่หน้าจอดูสมบูรณ์

## 6. สถานะของงานออกแบบครั้งนี้

เสร็จ: ตรวจสองเว็บไซต์และ API ตัวอย่าง เก็บหลักฐาน JSON/PDF ตรวจหน้าต้นฉบับหนึ่งรายวิชา ออกแบบกติกา mapping โมดูล หน้าจอ ข้อมูล รายงาน และแผนตรวจรับ

ยังไม่ได้ทำ: ซิงก์ครบทุกแหล่ง ติดตั้ง web/backend/database ออกคำตัดสินหรือผล mapping จริง ตรวจระเบียบเทียบโอนครบชุด สร้างรายงาน PDF ผลเทียบโอน ทดสอบกับผู้เชี่ยวชาญ หรือ deploy ระบบ ข้อเหล่านี้เป็นงาน implementation ตามแผน ไม่ควรรายงานว่าเสร็จแล้วจากชุดเอกสารออกแบบนี้
