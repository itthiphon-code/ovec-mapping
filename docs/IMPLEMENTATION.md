# สถานะการพัฒนา COMPASS 0.2

วันที่ 11 กันยายน 2569 — รุ่นสำหรับทดลองใช้งานและตรวจรับร่วมกับผู้เชี่ยวชาญ

รุ่น 0.3 เพิ่ม Embedding Matcher หลายภาษา พร้อมเปอร์เซ็นต์รายข้อ/ภาพรวมและเชื่อมอันดับแรกลงแถวว่างอัตโนมัติ ผลยังเป็นข้อเสนอรอผู้เชี่ยวชาญ รายละเอียดใน [EMBEDDING_MATCHER.md](EMBEDDING_MATCHER.md)

รุ่น 0.2.1 แก้การค้นหาเมนู: เพิ่ม `/automatic` และทางเข้าจากหน้าหลัก แสดงส่วนค้นอัตโนมัติตลอดพร้อมเหตุผลเมื่อปุ่มยังใช้ไม่ได้ การสร้างงานผ่านหน้านี้พาเข้าที่แท็บวิเคราะห์โดยตรง เพิ่มคู่มือบนเว็บและแสดงข้อผิดพลาดการตรวจสิทธิ์อย่างชัดเจน ตรวจผ่านเบราว์เซอร์จริงว่าบัญชีผู้ดูแลเข้าสู่ระบบ ค้นและเลือกรายวิชา แล้วเรียกค้นคู่มาตรฐานได้

## สิ่งที่พัฒนาแล้ว

- หน้าจอภาษาไทยแบบ responsive โทนสว่าง ใช้ CSS 3D ในส่วนภาพประกอบ แบ่งพื้นที่ข้อมูล งานเทียบ ผู้เชี่ยวชาญ เอกสาร คำร้อง และผู้ดูแล
- ค้นข้อมูลผ่าน API ที่ตรวจสอบของ DLES ทั้งรายวิชาและ TPQI เก็บรายการที่ค้นพบในฐานข้อมูล หากต้นทางไม่พร้อมแสดงข้อมูลที่เก็บไว้พร้อมสถานะ ข้อมูลเริ่มต้นเป็นรายการจริง 132 รายการ มิใช่คลังทั้งหมด
- ตรึงข้อมูลรายละเอียดรายวิชาและมาตรฐานในฉบับงาน เลือกระดับ UoC, EoC และเกณฑ์ PC จากต้นทาง เลือกหลายเกณฑ์ต่อหนึ่งข้อกำหนดได้ เพิ่มข้อกำหนดจากข้อความรายวิชาได้โดยตรวจกลับกับต้นฉบับ
- ไม่ยอมให้ลบข้อกำหนดเดิมเพื่อลดตัวหาร ความครอบคลุมนับข้อกำหนดข้อความที่ไม่ซ้ำ ทุกความสัมพันธ์ในข้อเดียวกันต้องครบจึงนับ FULL ข้อที่หลักฐานไม่พอยังคงอยู่ในตัวหาร ตัวเลขนี้ไม่ใช่จำนวนหน่วยกิต
- ตรวจอ้างอิงระดับก่อนยืนยันฉบับ คำค้นที่คล้ายหรือระดับตรงกันไม่ยืนยันมาตรฐานอัตโนมัติ ผู้จัดทำต้องเปิดเอกสารและระบุเหตุผล ผู้เชี่ยวชาญสองบทบาทและผู้อนุมัติเป็นคนละบัญชี
- ฉบับแก้ไขพร้อม hash ประวัติและ optimistic concurrency: งานที่เปลี่ยนระหว่างอ่านกับบันทึกตอบ 409 ความเห็นผูกกับ hash และฉบับ ผู้จัดทำรับรองตนเองไม่ได้ ผู้ดูแลไม่ได้สิทธิ์ผู้อนุมัติทางวิชาการโดยปริยาย
- PDF สูงสุด 15 MB จัดเก็บใน R2 พร้อม SHA-256 ผู้เพิ่ม ชนิดเอกสาร และวันเวลา ดาวน์โหลดเฉพาะเจ้าของ ผู้ดูแล หรือเจ้าหน้าที่ที่ตรวจคำร้องซึ่งอ้างถึงเอกสารนั้น ไฟล์ไม่มีสถานะรับรองความแท้จากการอัปโหลด
- รับคำร้องที่แนบเอกสารประเภทคุณวุฒิของผู้ยื่น ตรวจหลักฐาน ขอข้อมูลเพิ่ม และเตรียมประเมิน บล็อกสถานะตัดสินหน่วยกิตจนกว่าขั้นนโยบายและการพิจารณาจะพัฒนาครบ
- พิมพ์ตารางเทียบ สรุป บัญชีหลักฐาน และความเห็นผู้เชี่ยวชาญ แสดงสถานะร่าง/รับรอง เลขฉบับและ hash ส่งออก CSV ภาษาไทยและป้องกันสูตรจากข้อมูลเซลล์ การบันทึก PDF ใช้หน้าต่างพิมพ์ของเบราว์เซอร์
- จัดการสมาชิก บทบาท ขอบเขตและวันสิ้นสุดการแต่งตั้ง ระงับสิทธิ์ ชื่อหน่วยงาน นำเข้ารายการทีละหน้า และประวัติทำรายการ

## การตัดสินใจด้านสถาปัตยกรรม

เอกสารออกแบบเดิมเสนอ Next.js/PostgreSQL/S3 สำหรับระบบเต็มรูปแบบ รุ่นที่นำขึ้น Sites ใช้ React 19 + vinext App Router บน Cloudflare Workers, D1 (SQLite) และ R2 เพื่อให้มีข้อมูลคงทนและเอกสารส่วนตัวโดยไม่ต้องเตรียมเซิร์ฟเวอร์เพิ่ม Drizzle เก็บ schema และ migration ใน repository ไม่มีข้อมูลธุรกรรมเก็บใน localStorage

Sites ยืนยันตัวตนและส่ง `oai-authenticated-user-email` ผ่าน dispatcher แอปเชื่อถือ header นี้เฉพาะในสภาพแวดล้อมหลัง dispatcher ดังกล่าว ผู้เข้าระบบใหม่ได้บทบาทผู้เรียน การยกระดับสิทธิ์ทำผ่านผู้ดูแล บัญชี `itp@utc.ac.th` เป็นผู้ดูแลเริ่มต้นและปรับผ่าน runtime `ADMIN_EMAIL` ได้

เว็บไซต์เผยแพร่แบบส่วนตัวของเจ้าของก่อน การแต่งตั้งผู้เชี่ยวชาญในแอปไม่เพิ่มสิทธิ์เข้าชมของ Sites ผู้ดูแลต้องกำหนดกลุ่มผู้เข้าถึงที่ชั้นโฮสต์ก่อนเริ่มทดลองหลายคน ไม่ได้ส่งอีเมลออกจากระบบ

ไฟล์ `.env.local` / `.dev.vars`, ฐานข้อมูลและ R2 ใน `.wrangler`, รวมถึงข้อมูลทดสอบใน `tmp` ไม่เข้าสู่ Git หรือ artifact สำหรับเผยแพร่ การสวมบทบาททดสอบตรวจทั้ง development mode, loopback host และ local key; ไม่ทำงานบน production

## สิ่งที่ยังต้องพัฒนาก่อนใช้งานทางการ

1. ระบบลงทะเบียนฉบับนโยบายเทียบโอนที่มีผลใช้บังคับ เกณฑ์หน่วยกิต การตรวจคุณวุฒิกับผู้ออก การประเมินจริง และคำตัดสินรายบุคคลพร้อมอำนาจลงนาม รุ่นนี้มีการรับคำร้องและบันทึกขั้นตอนเท่านั้น
2. ดาวน์โหลดและเก็บเอกสารต้นทางทุกฉบับโดยอัตโนมัติ พร้อม hash ไฟล์ ตำแหน่งหน้า และการตรวจการเปลี่ยนฉบับ ปัจจุบันตรึง JSON รายละเอียดในงานและใช้ลิงก์เอกสารต้นทางให้ผู้จัดทำ/ผู้เชี่ยวชาญตรวจเอง รายละเอียดที่เก็บในคลังจะถูกใช้ซ้ำ ไม่ใช่ full refresh อัตโนมัติ
3. การนำเข้าเต็มคลังตามกำหนดเวลา ระบบคิว retry/reconciliation และติดตาม schema drift ปัจจุบันเป็นการค้นสดและการนำเข้าทีละหน้าโดยผู้ดูแล
4. PDF parsing/OCR และ malware scanning: รุ่นนี้ตรวจขนาดและส่วนหัว PDF เท่านั้น ไม่ได้ยืนยันว่าไฟล์ปลอดภัย อ่านได้ครบ หรือเป็นเอกสารแท้
5. ไฟล์รายงาน PDF ที่สร้างจากเซิร์ฟเวอร์และตรึงถาวร, QR ตรวจสถานะ, ลายมือชื่อดิจิทัล, DOCX และรายงานคำตัดสินเทียบโอนรายบุคคล
6. การบริหารขอบเขตผู้เชี่ยวชาญแบบรหัสอาชีพ/สาขาที่ตรวจอัตโนมัติ ปัจจุบันตรวจการมอบหมาย บทบาท ข้อความขอบเขต และวันหมดอายุ ผู้ดูแลต้องตรวจความเหมาะสมเชิงวิชาการของผู้ได้รับมอบหมาย
7. การเก็บและค้นย้อนหลังในปริมาณมาก, retention/backup/restore, สิทธิ์ระดับหลายสถานศึกษา และการตรวจ accessibility/print แบบเห็นหน้าจอจริงก่อนเปิดใช้วงกว้าง

ไม่ใช้ความคล้ายเชิงข้อความหรือ AI ตัดสินผล และไม่สร้างผลรับรองตัวอย่างขึ้นมาใน production รุ่น 0.2 เพิ่มข้อเสนออัตโนมัติจากรหัสอ้างอิงและคำร่วม แยกเก็บผลวิเคราะห์ตามฉบับก่อนให้คนเลือกใช้และให้ผู้เชี่ยวชาญตรวจ

## การตรวจสอบรุ่นนี้

- TypeScript, ESLint และ production build
- Unit tests 28 กรณี: ตัวหาร, ความสัมพันธ์หลายเกณฑ์, หลักฐานไม่พอ, ต่างระดับ, critical gap, ผู้ตรวจอิสระ, วันหมดอายุ, hash ของฉบับ และ URL ต้นทาง
- HTTP automation เพิ่ม 20 checks ครอบคลุมผลวิเคราะห์ที่ไม่แก้ฉบับงาน การใช้ข้อเสนอเฉพาะที่มีอยู่จริง ผลเก่า การข้ามงาน การต่างระดับ การรักษางานเดิม และคำแนะนำคู่มาตรฐานจาก API จริง
- HTTP integration 43 checks กับ worker และฐานข้อมูลจริงในเครื่อง: การดึงต้นทาง, บันทึก/แก้ไข, stale revision, สิทธิ์, ผู้เชี่ยวชาญสองบทบาท, การบล็อกเผยแพร่ก่อนรับรอง, อัปโหลด/ดาวน์โหลด, การเข้าถึงหลักฐานคำร้อง, ป้องกัน cross-site และการบล็อกคำตัดสินที่ยังไม่รองรับ ข้อมูลทดสอบระบุ TEST ONLY และลบแถวหลังทดสอบ ไม่เผยแพร่ผลทดสอบเป็นงานจริง
- ตรวจหลักฐานสำรวจ 11 ไฟล์ด้วย SHA-256 และ schema ตัวอย่าง ไม่ใช่การรับรองความครบของคลังทั้งหมด
- ตรวจ dependency production ไม่พบช่องโหว่จาก `npm audit --omit=dev` ณ วันที่ตรวจ การตรวจรวมเครื่องมือพัฒนายังพบ 6 รายการ (4 moderate, 2 high) ในสาย drizzle-kit/esbuild และ vinext/image-size ซึ่งยังไม่มี image-size รุ่นแก้บน npm ในวันที่ตรวจ ต้องติดตามอัปเดตก่อนเปิดใช้วงกว้าง รุ่นนี้ไม่รับอัปโหลดภาพหรือใช้ระบบปรับขนาดภาพจากผู้ใช้
- ยังไม่ได้ตรวจหน้าตาและการพิมพ์ด้วยเบราว์เซอร์แบบโต้ตอบ การเปิด localhost ในเบราว์เซอร์เชื่อมต่อถูกบล็อกโดยไคลเอนต์ แต่การทดสอบ HTTP และ build ทำได้
